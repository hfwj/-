2. [5ms模型修订工程，待本机验证](../../../downloads/设计1_IR2104模型修订_待本机验证.ms14)：保留原来的5ms终止时间、50ns最大步长、直流工作点初始化和原输出选择。用于继续测试2ms后的PWM启动。

## 修改了什么

只修改IR2104内部IN、SD两组比较网络，各两只电阻：

| 内部模型元素 | 原值 | 修订值 |
|---|---|---|
| R_MD1_TrigIN_R2 | 3.45Meg | 5.62Meg |
| R_MD1_TrigIN_R3 | 46.55Meg | 18.3Meg |
| R_MD1_TrigSD_R2 | 3.45Meg | 5.62Meg |
| R_MD1_TrigSD_R3 | 46.55Meg | 18.3Meg |

这四个元素属于芯片内部宏模型，不是图纸上的R_IN_PD或R_SD_PD。同步修改文件中模型的两份保存副本，并把活动模型ChangedByUser标为1。5ms工程的主电路、元件值、连线、3.3V测试信号及分析设置保持不变；1ms检查副本另外只修改活动瞬态分析的终止时间。

修订后独立测试的上升门限约2.892V、下降门限约0.798V，用于适配本工程0/3.3V输入。它是用户修订的兼容模型，不是厂家重新认证的模型，也不能据此标定真实芯片的逻辑阈值、开关损耗或时序。原工程保存在[references/user-projects](../../../references/user-projects/2026-10-24_设计1.ms14)，不覆盖。

6V只用于隔离测试，原生修订工程保持3.3V信号。独立测试采用5μs脉宽/10μs周期，目的是检验输入电平识别；用户功率级工程仍为1μs/10μs。独立测试的VB和VCC固定12V、VS接地、输出接1nF/100kΩ负载，不含真实Buck、自举充电及MOS功率级。

完整功率级的交叉求解中，原模型请求5ms、实际运行至4.581ms后在Q2内部VFI2支路出现步长过小；修订模型请求5ms、实际至2.000018ms后在Q1内部VFI2支路早退。修订模型在PWM之前的G_L恢复为约11.93V。另有1ms检查工况完整完成。上述均为ngspice结果；不证明Multisim本机也会出现同样的数值问题，亦未证明其已经消除。

FUSE_RATED含Multisim交互脚本，交叉求解只用其内置导通电阻1mΩ表示F1，未执行动画或熔断逻辑。原生副本保留原保险丝。该元件的动画减速因子会参与交互脚本的熔断延迟/电阻切换，不能一概当作只改变画面显示，也不能据此验证真实保险丝I²t特性。

## 复现

在仓库此目录运行；脚本根据仓库相对路径读取原工程。压缩包主要供本机打开工程，复现脚本建议在完整仓库中使用。

```bash
python -m pip install -r requirements.txt
python ms14_project.py
python verify_driver.py
python verify_power_stage.py
python build_delivery.py
```

上述是早期模型修订资料的复现流程。继续复现本次容差调整时运行`python stabilize_transient.py`和`python verify_startup.py`，详见[首次PWM切换排查报告](../../../reports/Multisim14_PWM首次切换步长过小_2026-10-24.md)。早期ZIP不包含后续新容差副本，最新文件直接从本页顶部链接下载。

`dclimplode`需要可用的C/C++编译器；若Python环境默认指定了不存在的clang，可设置`CC=gcc CXX=g++`安装。ngspice路径可通过`NGSPICE`设置；脚本加载同安装目录下的XSPICE代码模型。ngspice版本为44.2，使用PSpice兼容模式。

PKWARE DCL容器解压后得到ASCII XML。解析时保留属性中的原始换行，否则SPICE宏模型会被XML属性规范化折成一行。修改直接作用于原始XML文本，再按原容器分块重压缩；已检查字节数、解压回读、两个独立解压实现及主电路一致性。未将原始XML或独立厂家库另行发布。

当前工程仍是开环功率级/驱动测试，尚未加入完整采样、故障锁存及STM32闭环；不能据此认定G题恒压恒流、效率或保护全部完成。
