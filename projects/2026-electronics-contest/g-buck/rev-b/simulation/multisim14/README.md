## 向导提示 multiple top-level .subckt statements

此报错说明向导只接受一个顶层子电路。当前models目录的三个模型副本均已将辅助`MOS_SWITCH_EQ`嵌套在主`GBUCK_REVB_EQ`内部；所有`.MODEL`也都位于主模型或内部辅助子电路内。文件末尾依次为`.ENDS MOS_SWITCH_EQ`和`.ENDS GBUCK_REVB_EQ`。此前两个子电路并列的文件需要更新，不能只去掉开头注释。

手动修正旧模型时，将辅助子电路前面的那一行`.ENDS GBUCK_REVB_EQ`剪切至文件最末尾即可，保留其余电路。17端口、参数和元件行不变；9个完整测试网表仍保留原布局，以免混淆其完整求解证据。新版向导模型另跑25V/8Ω的0～80ms核验并比较原输出波形，见[wizard_nested_model_check.json](results/data/wizard_nested_model_check.json)；该检查使用ngspice，仍不代表Multisim本机导入通过。

## 已修复：标题被当作G受控源

旧版`.cir`首行是`G problem Rev B / ...`。某些导入入口不把首行当成标题，会把首个`G`当作元件名，于是把`/`、`PSpice`、`style`等文字误解析为电流源增益表达式。若看到这组错误，先选择不继续，把首行前加`* `，再重新导入；也可重新下载当前修正版。

例如`04_25V_8ohm.cir`首行应为：

```spice
* G problem Rev B / 04_25V_8ohm / PSpice-style functional circuit
```

只修正这行说明文字，不要删除真正的`GCORE`、`GAUX`、`G_XV`等受控源。本次已同步修正9个网表和生成器；电路与元件参数没有改变。已有完整工况数据保留原实际求解的源哈希，另记注释修订前后正文相同的证明。当前修订仍未在Windows版Multisim实际复测，不能据此承诺其他解析差异也已消除。

## 一、先搭这一张：25V输入、8Ω负载

这个工况最直观：恒流工作时应约8V/1A，而不是10V/1A。电路由一个导入的功能组件和外部电源、负载、地、探针组成；功能组件内含按Rev B重建的完整功率级及等效控制链。

### 1. 用组件向导导入

在Multisim 14.0中使用`Tools → Component Wizard`（工具→元件/组件向导；中文名称可能随版本语言不同）。目标是建立**仅仿真用的自定义组件**，不要分配PCB封装。

1. 组件命名`GBUCK_REVB_EQ`，引脚数量设为17；选择可表示17引脚的矩形符号，给引脚添加下面的名称。
2. 到SPICE模型步骤，载入当前`models/G_BUCK_RevB_EQ.lib`；如果能编辑模型文本，也可粘贴`models/G_BUCK_RevB_EQ.txt`全文。模型数据须直接以`.SUBCKT`开头，且只有GBUCK_REVB_EQ一个顶层子电路。只有文件筛选器不显示.lib时才选同内容.cir副本。**保留主模型内部的`MOS_SWITCH_EQ`子电路和全部`.MODEL`定义**，主模型的`.ENDS GBUCK_REVB_EQ`必须位于文件最后。具体入口需以本机页面为准。
3. 按下面表格做“符号引脚→模型端口”的映射。序号取自`.SUBCKT`声明顺序，不是实物芯片脚号。
4. 保存到User Database（用户数据库）的自定义组，在原理图中放置该组件。

如果安装版本的向导布局不同，以“仿真组件、17端口、导入整个SPICE模型、核对引脚映射”为准。该模型不是IR2104或STM32的元件模型，不要把它命名成这些真实芯片。

### 2. 外部电源与信号设置

- `VIN_EXT`使用25V直流电源，负端接地。
- `VSET`和`ISET`是控制设定信号，不是辅助供电。分别用10V、1V直流源，负端均接地。
- VSET/ISET是新增的**仿真接口**，不是Rev B实物MCU引脚；不能据此把10V接入STM32。修改设定值时还需检查当前占空比范围，低电压/低电流设定未加入跳脉冲算法，不能保证任意设定值均可实现。
- ARM脉冲：低0V，高3.3V，延时5ms，上升/下降各10ns，脉宽10us，周期1s。SPICE写法为`PULSE(0 3.3 5m 10n 10n 10u 1)`。
- MCU_EN用分段线性电压源：`PWL(0 0 5.1m 0 5.101m 3.3)`。没有方便的PWL元件时，可用脉冲源低0V、高3.3V、延时5.1ms、上升/下降10ns、脉宽1s、周期2s，在本次80ms观察窗口内保持高电平。
- 负载是8Ω电阻，接在VOUT与地之间。
- 12V、5V、3.3V轨已在功能组件中生成并按假设折算输入功耗，不要再在外部给这些内部节点并接理想电源。

模型先等待模拟电源/参考建立，5ms ARM，5.1～6ms低侧自举预充，6～16ms软启动。这些时间为本次可复现测试的设定，不是原理图规定的固定延时。

### 3. 瞬态分析设置

使用Transient Analysis（瞬态分析）：开始时间0，结束时间80ms，最大时间步长100ns。选择电容/电感初始状态为零，对应`.TRAN 100n 80m 0 100n UIC`，避免先用静态工作点初始化含开关控制和锁存状态的电路。

先观察VOUT、ADC_IOUT和FAULT_N；再把时间窗口缩小到最后100us，观察GH_MON、GL_MON及BOOT_MON。

- VOUT应由软启动上升，8Ω时最终约8V。
- 外部负载电流取`VOUT/8`。ADC_IOUT还包含输出泄放和分压电流，不能把它完全等同外部负载电流。
- GH_MON/GL_MON应有互锁的栅源电压波形；两路都为低时为死区或停机。
- BOOT_MON应建立足够高的正电压。模型的高侧使能门限为8V，是功能假设，不是IR2104保证的UVLO模型。
- FAULT_N稳定后应保持高。故障消失不会自动恢复SAFE，需要新的ARM上升沿。

### 4. `.cir`文件如何使用

`circuits/04_25V_8ohm.cir`包含上述电路的全部SPICE定义。若当前安装提供SPICE网表打开/导入入口，可尝试直接载入；**没有相应入口时使用上述组件向导方案**。不能保证打开`.cir`会自动生成可编辑的多器件原理图，不能把后缀改为`.ms14`冒充原生工程。

## 二、按原理图逐个放元件的接线

若希望在Multisim中看见独立元件，而不是单个等效模块，按接线图第1～3页搭建。主功率连接顺序是：

```text
VIN_EXT → F1等效20mΩ → D1 → RS_IN(50mΩ) → VIN
VIN → QH漏极；QH源极 → SW
SW → QL漏极；QL源极 → GND
SW → L1(220uH) → DCR(150mΩ) → RS_L(25mΩ) → V_CAP
V_CAP → C3(470uF，串80mΩ ESR) 与 C4(10uF) → GND
V_CAP → RS_OUT(50mΩ) → VOUT → 外部负载 → GND
VOUT → R_BL(2.2kΩ) → GND
VIN → C1(470uF) 与 C2(1uF) → GND
```

`D1`阳极朝VIN_EXT，阴极朝VIN；QH体二极管阳极SW、阴极VIN；QL体二极管阳极GND、阴极SW。RS_L位于输出电容之前，RS_OUT位于输出电容之后，不能交换。

显式串联了150mΩ的L1应采用零内部电阻的理想电感；C3显式串联80mΩ时，也不要再次在电容内部设置相同ESR，避免重复计算。

### 器件库与替代方式

- 电阻、电容、电感、地、直流/脉冲源使用Multisim通用模拟元件。
- 功能模型的QH/QL是带体二极管的受控开关，44mΩ导通电阻；不是IRF540厂家晶体管模型。
- 如果本机数据库具有带仿真模型的IRF540，可在单独副本中替换功率开关，并核对其模型D/G/S端口；若没有，使用厂家提供的兼容模型通过向导导入。不能仅凭符号名称认定模型正确。
- 换成真实MOSFET模型后，移除原`MOS_SWITCH_EQ`及其体二极管；若模型已包含栅电容，也移除外加的`C_GH_EQ/C_GL_EQ`，避免重复建模。保留原图10Ω栅电阻、10kΩ栅源下拉和自举网络，然后重新验证。
- IR2104、INA240、INA181、LM393、HC74/HC14在本搭建包中由明确的功能电路替代，不依赖本机一定包含这些库元件。需要真实芯片级验证时，应逐块换成经核对的厂家模型并重新跑工况。

### 驱动必须注意

高侧栅极通过10Ω接HO，HO相对SW驱动；高侧10kΩ下拉接SW，低侧下拉接地。自举二极管从12V指向VB，自举电容1uF跨VB与SW。

本模型用50Ω上拉、25Ω下拉的受控开关替代驱动输出级，加上两只假设4.7nF栅源电容，能观察自举电容充放电。其源/灌电流、UVLO、死区、米勒效应均不是厂家保证模型。因此不能用其波形证明真实IR2104/IRF540无直通或实际效率达标。

### 采样、控制与保护

- U2：IN+=V_SHUNT_IN，IN−=VIN，增益20，50mΩ产生1V/A。
- U3：IN+=V_CAP，IN−=VOUT，增益20，50mΩ产生1V/A。
- U4：IN+=L_RAW，IN−=V_CAP，输出V3A/2+0.5V/A×IL。
- 五路ADC各有1kΩ/4.7nF，输入/输出电压分压均11:1。
- 正负电流、过压参考电阻按原图保留，比较器使用原始IL_BI/VOUT_DIV，不经过ADC支路滤波。
- FAULT_N为开集电极等效汇合并上拉3.3V，清零SAFE；ARM上升沿恢复，DRV_EN=SAFE AND MCU_EN。
- 这个等效控制自动根据电压误差限制电感目标电流，不通过人工切换CV/CC来获得测试结果。

## 四、模型假设与适用范围

- 保留原图功率参数与采样/参考网络，但M1/M2由理想电源轨及折算输入电流源代替。辅助转换效率假设各85%，5V控制/显示电流假设60mA、3.3V模拟偏置总电流假设5mA、驱动静态电流假设1mA；这些不是用户物料的实测数据。
- 电感DCR取0.15Ω、C3 ESR取80mΩ；C4不含降容，电感不含饱和及磁芯损耗，F1不含熔断行为。
- MOS导通44mΩ、开关门限6V、体二极管、SS56/UF4007二极管参数均为近似，不是厂商模型。4.7nF仅为仿真电容，不改变BOM。
- 每只开关另有250pF固定漏源寄生电容，避免两管关闭时SW节点的理想化换流问题；它不是实物新增元件，也不是厂家非线性Coss曲线或米勒电容模型。换真实MOS模型时同样应移除这项额外等效电容。
- 原图中的ADC钳位二极管在此正常范围模型中未实现，因此不能验证ADC过压保护。
- 理想控制源替代了GPIO、PWM串联/下拉电阻等接口细节，部分电源去耦和逻辑动态耗电未逐件建模；该模型不能作为96个实物器件的逐引脚完整验证。
- 连续PI替代STM32：电压环Kp=0.5、Ki=50；电感环Kp=0.15、Ki=200，含抗饱和、V_CAP/VIN前馈、−0.3～ISET电流目标、0.08～0.88占空比。
- PI中的1F积分电容、锁存/ARM边沿网络和放大器等效RC仅表示数学状态或响应近似，不是原图新增器件，不应加入采购清单。
- 电压反馈与电感反馈使用本模型的ADC支路；未模拟ADC采样保持、量化、F103中断执行、LCD和按键。空载允许有限负电流，不等同于禁止反流/跳脉冲固件。
- 上电参考建立后ARM，POR与锁存用模拟行为状态近似，未验证HC芯片的建立/保持时间、输入门限容差或真实上电复位。
- 同一外部Ui提供辅助功耗的等效输入，避免把辅助功率排除在电路外；即使算出效率超过85%，仍不能据假定耗电和开关模型宣布实物整机达标。
- 输出电容放电会使阶跃负载电流瞬时超过1A；±1.8A标称保护不是1A正常恒流环。3V3_A经10Ω供电，有压降时门限和电感零点会偏移。
- 短路时如果控制环将电流维持在1A附近，未达到过流门限就不会触发该过流锁存。没有加入原资料未提供的软件欠压/短路锁存，不能承诺所有短路都会自动停机。短路停机结论依赖具体控制与驱动模型，不能直接沿用另一版行为模型的结果。

## 五、常见问题

| 现象 | 检查 |
|---|---|
| 始终没有输出 | COM是否接地；ARM是否在5ms给出上升沿；MCU_EN是否在5.1ms后为3.3V；FAULT_N是否为高；初始条件是否归零 |
| 8Ω输出约8V，不是10V | 这是1A恒流工作点，正常；20Ω才应约10V |
| 两个栅极看似电压不对 | 观察GH_MON/GL_MON；真实G_H需测G_H−SW，不应只测G_H对地 |
| 模型找不到MOS_SWITCH_EQ | 导入时丢失了辅助.SUBCKT；载入完整.lib |
| IF/LIMIT/VALUE语法报错 | 核对载入的是SPICE/PSpice兼容模型、函数大小写和完整大括号；保存错误文本以便按本机14.0解析器调整，不要改成.ms14后缀 |
| 元件G报未知变量PSpice/style/functional或无法解析斜杠 | 使用修正版，或给首行`G problem...`前加`* `，只修改标题，不要删除真正的G受控源 |
| 显示悬浮节点/奇异矩阵 | COM必须是全局地；VSET/ISET/ARM/MCU_EN全部有确定源；模型端口顺序必须一致 |
| 仿真很慢 | 开关频率100kHz且最大步长100ns，80ms包含8000个周期；先单独跑04，观察0～25ms确认启动，再延长至80ms。后者才作为稳态结果 |
| 故障后恢复负载仍不重启 | 故障锁存的预期行为；需先确认故障解除，再给新的ARM上升沿；真实电路还需检查残压后受控重启 |

## 六、维护和核验

普通Multisim用户不需要安装Python或ngspice，按组件向导搭建即可。维护者在此目录可运行：

```bash
python build_circuits.py
python draw_circuits.py
python make_wizard_guide.py
python check_import_headers.py
python check_wizard_model.py
MPLCONFIGDIR=/tmp/buck-mpl python verify_equivalents.py
python package_delivery.py
```

`verify_equivalents.py`只对临时副本增加ngspice控制命令，使用`ngbehavior=psa`核对PSpice风格表达式、启动、正常工况和指定停机行为，保存原始求解日志、压缩波形和数值汇总。它不会生成`.ms14`，也不会把ngspice结果标为Multisim通过。

`check_wizard_model.py`验证新版向导模型只有一个顶层子电路，全部依赖定义均在其内部，并在原25V/8Ω测试电路中替换成嵌套模型运行0～80ms。完整单工况复核与原9工况证据分别保存，不将原有数据冒充新版全部工况实测。
