# ADCFIX1 / A1：ADC采样时间修正与上板复测

日期：2026-11-03（北京时间）。源码比较基准：`16c6e675947681a9e10155302117c70150e9f457`；原始固件/镜像为2026-10-28版本。A1是新的禁止功率输出诊断版，屏幕标题为 `GBUCK C2 LOCKED A1`。

## 用户报告与确认缺陷分开记录

以下为对话中用户报告的测量与照片，未独立连接硬件测量，也没有启动波形：

- 旧诊断HEX烧录、校验成功，LCD显示正常。
- 初期PB10、PB11稳态高，PA4约为3.3V的一半；FAULT线断开时为OFF/FAULT 0，恢复后通过命令1由FAULT 1转为FAULT 3。不能据此证明故障链全部正常，启动瞬态仍未定位。
- 辅助模块临时供电隔离曾在预充后VIN节点测得15V，之后用户报告隔离复测为0V，两只MOS管静态VGS均为0V。这不是动态关断或MOS管本体验收。
- 后续主输入采样检查中，用户报告J1.1=15V、J_CTL.11=1.35V、核心板PA0=1.35V；照片仍显示VIN=0、POST=14.883V、IL=-0.028A、FAULT 3。

源码中确认的错误：`board_init()`把实际使用的ADC通道0/1/2/3/4/6的采样时间写到了`ADC1+0x0C`（SMPR1，负责通道10～17）。这些实际通道因此仍使用SMPR2中的复位采样时间1.5周期，而不是文档声明的239.5周期。

修正为SMPR2（`ADC1+0x10`），对0/1/2/3/4/6分别设置239.5周期，PA5仍只用于LCD。地址和通道字段依据[ST官方STM32F103xB CMSIS头文件](https://github.com/STMicroelectronics/cmsis-device-f1/blob/master/Include/stm32f103xb.h)中的ADC_TypeDef、ADC_SMPR1_SMP10_Pos和ADC_SMPR2_SMP0_Pos/SMP6_Pos核对。

**这是一处确定的源码错误，但没有足够证据证明它是VIN固定为0的唯一或实际根因。** A1必须上板复测；不以代码修正代替ADC、芯片焊接、VDDA/VSSA、寄存器状态或MCU型号核查。

## 本次变更

- 修正SMPR2配置，不更改通道顺序、比例、PI参数、故障门限或故障锁存/恢复策略。
- 增加只读观察变量`debug_adc_raw[6]`（每项32位，依次PA0/PA1/PA2/PA3/PA4/PA6）、`debug_adc_scans`（完整扫描次数）和`debug_adc_failures`（采样超时次数）。原始值为0～4095；没有数据时计数为0。读取多字快照前后检查扫描次数，跨扫描时重读；这些变量不是命令入口。
- 默认LCD标题增加A1；POWER=0仍始终禁止EN、ARM及PWM功率输出。
- 新增调用真实`board_init()/board_sample()`的Linux主机寄存器模型回归测试。模型只模拟时钟就绪、校准完成和ADC返回值，不模拟真实电容建立时间、ADC误差、转换时序或保护硬件。

## 已执行验证

- 修正前，寄存器模型测试在通道0的SMPR2采样时间断言失败；修正后通过。另覆盖模拟GPIO、PWM关断、六通道顺序、数据到物理量转换、ADC超时返回失败。
- `make test`：原有主机ASan/UBSan状态机测试、POWER=0锁定测试和新增寄存器模型测试全部通过。
- GCC 12.2.1，三配置交叉编译，`-Wall -Wextra -Werror`：p0-k0-l1、p0-k0-l0、p1-k1-l1。p1仅用于编译兼容检查，不发布其预编译镜像，不代表允许功率测试。
- A1默认text=4844、data=24、bss=260字节，静态RAM=284字节；链接脚本仍限制64KB Flash / 20KB RAM并保留2KB栈空间。
- 默认反汇编确认`board_outputs()`无条件调用`board_kill()`并拉低ARM。另检查三配置向量/Flash范围、Intel HEX记录校验和及其与BIN逐字节一致，见`build_manifest.json`。
- 8MHz ADC下，六次239.5周期采样加12.5周期转换的理论总时间约189微秒，不含软件开销；真实ISR总时间、抖动及1ms预算仍待实测。原固件已有DWT超时锁存，本次不屏蔽它。

没有真实目标板可由本环境连接；**A1尚未上板验证，不声称VIN显示问题已解决，不用于闭环功率测试**。

## 下载与复测

- [单独HEX](../../downloads/GBUCK_RevC2_diagnostic_ADCFIX1_2026-11-03.hex)
- [源码、默认HEX/BIN/ELF/MAP及校验清单](../../downloads/GBUCK_RevC2_STM32_diagnostic_ADCFIX1_2026-11-03.zip)
- [文件SHA256](../../downloads/GBUCK_RevC2_ADCFIX1_2026-11-03.sha256)

1. 断开主输入及其他电源、确认电容放电后，使用原已验证的SWD接线和单路核心板供电，烧录A1 HEX并勾选校验。HEX地址自带0x08000000。此次只是烧录，主功率输入不接，不并联USB/调试器/辅助电源输出。
2. 确认BOOT0=0，断开软件连接并复位，先确认标题为`GBUCK C2 LOCKED A1`。
3. 按原已核对的接法恢复供电；POWER=0、旁路断开、15V受限流输入，持续限流/异常发热即停止，不提高电流掩盖异常。比较J1实际电压、PA0电压、屏幕VIN与PA6/POST。1.35V采样应对应约15V；VDDA默认按3.300V计算，用户此前测得约3.25V，存在比例误差，不能当作标定完成。
4. 如果PA0仍为约1.35V而VIN为0，通过Hot Plug读取下面的RAW及计数。RAW0和RAW5应与实际PA0/PA6及VDDA对应；PA0=1.35V、VDDA约3.25～3.3V时，RAW0应约1675～1701。计数不增长/超时增长与稳定RAW0=0是不同分支，需要分开查，不直接补偿或绕过故障。

下表**仅适用于本次打包的p0-k0-l1 A1镜像**，以包内MAP与manifest为准。重编译后地址可能变化。

| 地址 | 32位内容/操作 |
|---|---|
| 0x2000001C | debug_adc_failures，只读 |
| 0x20000020 | debug_adc_scans，只读，应持续增长 |
| 0x20000024～0x20000038 | 六个RAW值，只读；一次读取0x18字节 |
| 0x2000003C | debug_sample.vin，只读，mV |
| 0x20000098 | debug_value，命令参数 |
| 0x2000009C | debug_command，命令入口，处理后归零 |

**旧版0x2000007C不再是命令入口，禁止沿用。** 不随意修改快照、RAW、app或hard_fault。命令1只在实际FAULT_N健康时清除软件记忆并重新检查；并不代表实体旁路已闭合，也不自动启动。上电再次FAULT 1时，先记录并核查FAULT_N，不能将所有启动故障都当作正常。

## 修改影响

- 原理图：相对上述基准，不改拓扑、端口/脚位、阻容值；PA0～PA4、PA6仍为原通道。
- 器件/BOM/PCB：本修正不要求换件、飞线或改板；实物采样异常的硬件根因仍未排除，不能据此证明原板无缺陷。
- 固件：ADC建立时间实际变长，增加诊断RAM变量及LCD版本标识；所有硬编码SWD变量地址需重新核对。控制与保护算法、POWER=0互锁不变。
- 仿真/模型：不修改Multisim/SPICE、激励、元件模型或求解设置。主机寄存器模型只用于软件回归，不等同于电路仿真或硬件测量。
