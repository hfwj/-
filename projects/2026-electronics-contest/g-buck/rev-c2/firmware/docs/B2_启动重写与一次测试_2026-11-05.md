# Rev C.2 B2 受限台架固件（2026-11-05）

[BENCH B2 HEX下载](../../downloads/GBUCK_RevC2_B2_2026-11-05.hex) · [完整源码补丁](../../downloads/GBUCK_RevC2_B2_source_2026-11-05.patch) · [构建与SHA256清单](../../downloads/GBUCK_RevC2_B2_manifest_2026-11-05.json)

基准为 B1（2026-11-04），针对用户报告的 **STARTUP/SOFTSTART 直接 FAULT、未观察到 RUN、未捕获波形** 重写控制与诊断。该现象尚不能定位为硬件驱动、连接或控制器单一原因。B2 未上板，不是最终功率固件。

源码保存在独立 `firmware/b2/`，不覆盖 A1/B1。公开的完整源码补丁只新增此目录，可在仓库根目录执行 `git apply 下载的B2_source.patch`；也可在空目录执行同一命令取得完整工程。预编译 BENCH B2 HEX 为 `POWER=1 LCD=1`；源码默认 `make` 是禁止输出的 LOCKED B2，二者均上电 OFF、禁止自动重启。

## 本次实际修改

- 启动不再仅按时间切换 RUN。300ms 电压目标斜坡后，实测 CV 电压/电流或 CC 电压/电流满足条件持续 100ms 才进入 RUN。没有足够电压上升在 250ms 报 F8，响应不足最迟 1s 报 F9；不通过延长或取消原保护假装启动成功。
- CV 使用输入电压前馈加有界 PI 修正；CC 在低电流时跟踪实际请求，接近设定时限制占空比，避免由零占空比缓慢开放。上升限速每毫秒20基点。此控制器已通过近似 LC 主机回归，尚未进行实机整定。
- 保留硬件故障输入、PB10 EXTI 优先关断、PB11 连续20ms软件判据、输入/ADC检查、3V软件过压；输出曾升起后跌落20ms会锁存。新增两次连续1kHz采样的400mA输出/±800mA电感电流保护，不能代替硬件峰值保护。START/ARMING 已知超过这些电流值时立即拒绝启动。
- 预偏置须不超过 `min(100mV,Vset/4)`；这是放电后启动的容差，不支持带电池、外部电源或预充输出的同步启动。
- ARM 2ms高、2ms关断等待后才进入 STARTUP。下一个控制周期读取本地 PB1/PB0：请求高而本地引脚低分别报 F12/F13；这不能验证排线另一端、SAFE_OK 或 DRV_EN。
- 第一次故障先记录状态、采样、占空比/PI请求和 GPIO/TIM1 信息，再清输出。屏幕保留原因、故障前电压、占空比及状态。STOP保留记录，PRECHARGE/CLEAR_RECORD或成功的新START才开始新记录。
- 固定 SWD 地址、命令回执、256条环形轨迹（每条10字、正常每5ms及状态/EN/ARM改变时记录），首次故障冻结。硬件 EXTI 先关断，若快照已在关断后采到，会标记 `AFTER_KILL=1`，不伪称故障前寄存器。
- LCD 初始化及看门狗启动完成前拒绝预充/旁路确认/启动命令。看门狗不因调试暂停冻结；用 Hot plug 实时读内存，不暂停CPU做通电测试。

## 限制、编译与复现

默认及最大设定 **2.000V / 0.200A**，允许电压200–2000mV、电流100–200mA；25%占空比上限，VIN须12–16V，POST≥11V且与VIN相差≤1.5V。200mA是控制目标，不能保证瞬态峰值。无按键控制，仅SWD命令。

```sh
cd projects/2026-electronics-contest/g-buck/rev-c2/firmware/b2
make                         # POWER=0，禁止功率输出
make POWER=1                 # 同下载BENCH镜像，仍上电OFF
make test                    # 主机控制/采样寄存器/诊断/中断适配测试
python3 tests/verify_image.py build/p1-l1
```

需要 GNU Arm Embedded GCC、Make、主机GCC/Python3；验证工具链为 arm-none-eabi-gcc12.2.1。不同编译器可得到不同校验值。所有ARM配置均限真实64KB Flash/20KB RAM；链接脚本留≥2KB栈空间。HEX自带Flash地址，BIN基址0x08000000。

## 一次完成的上板操作

1. 断电换线/接负载。沿用已经核实的 C.2 排线、辅助12V/5V/3.3V及共地；电源15V、限流0.1A，保持CV。接10Ω、至少5W电阻负载；没有合适负载先停在READY。启动前用已验证的放电方式使输出低于100mV，不直接短接带电电容。不要接电池或提高功率。
2. CubeProgrammer烧录并勾选校验 **BENCH B2 HEX**；BOOT0=0，运行后标题须为`GBUCK C2 BENCH B2`且状态OFF。若擦写失败，功率输入断开，ST-Link共地、100kHz、NRST配合Connect under reset再烧录。烧录时不要依赖故障记录保存，复位会清记录。
3. **所有A1/B1旧命令地址停止使用。** B2数据宽度32位，命令地址固定 **0x20000010**，值地址 **0x20000014**。先等约1秒，读0x20000000、长度0x100，开头必须`42324332 00020001 00000040`；FLAGS位2=1表示初始化完成。只写CMD和VALUE，不改状态、GPIO/TIM1或其它RAM。
4. 在CMD写`00000001`（PRECHARGE），等至少0.2秒至READY。按原台架流程确认物理旁路已正确接好，再写`00000002`（CONFIRM_BYPASS），屏幕显示BYPASS CONFIRMED。**软件命令不驱动、检测或验证物理旁路。** 写`00000003`启动一次，不连续重试。写`00000004`随时STOP。
5. 启动后等1–2秒，只需保存一张屏幕照片和一次 **0x20000000、长度0x100、32位**的完整读取；保持CPU运行。若FAULT，不再复位或写PRECHARGE/CLEAR；首故障字段和轨迹保持冻结，一次读取可用，当前值/计数可能跨越不同毫秒。电源进CC、主控重新发热或电流异常则直接停电。0x200000F8的序号可选用于快速读取一致性校验：前后相同且为偶数说明同次快照；低速SWD不一定能做到，不要为此反复读取或暂停CPU。

设定修改仅OFF/FAULT允许：先往VALUE写十进制毫伏/毫安，再往CMD写5/6；如2000=`000007D0`，200=`000000C8`。默认值已正确，首次无需修改。命令回执：0x18为计数，0x1C为结果（0接受、1状态不允许、2参数错误、3LOCKED版禁止、4未知命令）。输入命令会被清零表示已消费，不等于执行成功。

## 固定诊断窗口

每个地址为32位字；电压mV、电流mA、占空比基点（10000=100%），负数按有符号补码解释。状态：0OFF、1PRECHARGE、2READY、3ARMING、4STARTUP、5RUN、6FAULT。

| 偏移（加0x20000000） | 字段 |
|---|---|
| 00 / 04 / 08 / 0C | magic / ABI / 64字长度 / FLAGS：bit0允许台架输出、bit1轨迹冻结、bit2初始化完成 |
| 10 / 14 / 18 / 1C | CMD / VALUE / ACK_SEQ / ACK结果 |
| 20 / 24 / 28 / 2C | 当前状态 / 当前故障 / Vset / Iset |
| 30 / 34 / 38 / 3C / 40 / 44 | VIN / IIN / VOUT / IOUT / IL / POST |
| 48 / 4C / 50 / 54 / 58 / 5C | 当前duty / EN请求 / ARM请求 / tick / 成功扫描 / ADC失败 |
| 60 / 64 / 68 / 6C | 故障记录有效 / 首故障码 / 故障前状态 / 故障tick |
| 70 / 74 / 78 / 7C / 80 | 首故障VOUT / IOUT / IL / VIN / POST |
| 84 / 88 / 8C / 90 | 首故障duty / CV请求 / CC请求 / 记录flags |
| 94 / 98 / 9C / A0 / A4 / A8 / AC | GPIOB_IDR / CCR1 / 保留忽略旧CMD / BDTR / TIM_CR1 / CCER / GPIOB_CRL |
| B0 / B4 / B8 / BC / C0 | 最近命令 / 命令序号 / 轨迹基址 / 容量256 / 每条10字 |
| C4 / C8 / CC / D0 / D4 | 轨迹条数 / 下一写入索引 / 冻结 / PB1高观察次数 / PB0高观察次数 |
| D8 / DC / E0 / E4 / E8 / EC | EXTI次数 / ISR已测周期最大值 / 本次最大VOUT / 启动ms / 当前GPIOB_IDR / 控制目标 |
| F0 / F4 / F8 / FC | 六个RAW值数组地址 / AFTER_KILL / 一致性序号 / END2标识 |

记录flags：bit0采样有效，bit1FAULT_N高，bit2OC_N高，bit3EN请求，bit4ARM请求，bit5CC选中，bit6软件旁路确认，bit7输出已升起。D0/D4是本地高电平被扫描到的次数，不代表远端连线正常或脉冲宽度合格。DC包含控制及诊断工作到末端测量点，仍非外部示波器实测ISR延迟。

轨迹基址固定0x20000100，总0x2800字节。每条依次为tick、state/fault/EN/ARM打包、VIN、POST、VOUT、IOUT、IL、duty、GPIOB_IDR、CCR1/MOE/CEN/CC1E打包。未满从0读；满后从NEXT索引环形读取，最后一条在NEXT-1。最终故障条目duty为故障前请求，其状态为FAULT；首故障前状态以记录0x68为准。末字低16位CCR1，bit16MOE、17CEN、18CC1E。故障前硬件快照最多比首故障样本早一个1ms周期；EXTI后采到则AFTER_KILL=1。

## 测试证据及未测项目

- ASan/UBSan控制回归：手动互锁/边界参数、ARM2ms+等待2ms、无响应故障、实测启动完成、STARTUP/RUN保护、首次故障及STOP保留、ADC单位转换。
- 用户B1照片数据回放：VIN14960、POST13828、VOUT8、IOUT0、IL−12，产生非零PWM请求后在STARTUP报F8，保存这些采样与故障前非零占空比；不据此断言实板PWM存在。
- 实际main.c适配层主机测试：看门狗前命令拒绝、已接受预充才清旧锁存、临界区新故障不丢失、待决边沿/低故障线、ARM/EN回读、STOP及旧地址不启机。寄存器模型测试SMPR2、0/1/2/3/4/6采样和超时，仅主机证据。
- 真实C控制器+近似平均LC：Vin13.8V、L220µH、C470µF、DCR0.15Ω、1kHz控制/1µs RK4。10Ω/8Ω/5Ω约404ms进入RUN，末段均值分别1.9921V/0.1992A、1.5971V/0.1996A、0.9995V/0.1999A。这不是厂家MOS模型，未包含驱动死区/传播、开关寄生、ADC通道滤波/延迟、真实标定、硬件比较器和真实电源瞬态，不能推出硬件稳定性/效率。
- 两种ARM镜像编译、64KB/20KB范围、固定RAM区、向量Thumb地址、HEX逐行校验和与BIN字节一致性均检查。
- **未上板；G—S实际波形、同步死区、已跳过的物理故障刺激、峰值电流、闭环稳定性及硬件故障根因仍未验证。** 普通两通道CH1−CH2只可辅助观察高边，不能替代同步两路VGS/死区测量；两探头地均接已确认COM，不能夹SW，不能断示波器保护地。初步台架通过也不授权提高电压/电流或连接电池。

## 对原理图、器件及模型的影响

比较基准：B1台架镜像/源码（2026-11-04）与Rev C.2既有硬件。原理图网络/拓扑、PA/PB脚位及阻容值不改；器件/BOM、封装及PCB不改，本程序不要求换器件。外置假负载属于台架用品。实体 `.ms14` 与既有模型不改；新增近似LC仅用于执行真实C控制器的主机回归。修改了控制律、启动判据、诊断ABI及软件保护，B1旧测试不能作为B2实板验收。旧主控损毁原因仍未确定，本修改不证明已消除其原因。
