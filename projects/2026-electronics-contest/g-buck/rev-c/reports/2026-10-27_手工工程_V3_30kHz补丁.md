# 手工搭建工程：V3 30 kHz 补丁

比较基准：用户在 2026-10-27 上传的 `GBUCK_REVC_DRIVER.ms14`，原件按字节保存在 [references/user-projects](../references/user-projects/2026-10-27_GBUCK_REVC_DRIVER_手工搭建基准.ms14)。下载 [修改版 GBUCK_REVC_DRIVER_30k.ms14](../downloads/GBUCK_REVC_DRIVER_30k.ms14)。本补丁不将手工工程同步到另一个 Rev C.1 硬件版本。

## 修改内容及影响

仅替换 V3 的两份等效控制模板（活动模板及其缓存副本）内的两行：

```spice
* 修改前
XCTRL %t1 %t2 VOUT V_CAP 7 L_RAW GBUCK_CTRL_EQ
V_SAW SAW COM PULSE(0 1 0 9.98u 20n 0 10u)
* 修改后
XCTRL %t1 %t2 VOUT V_CAP VIN L_RAW GBUCK_CTRL_EQ
V_SAW SAW COM PULSE(0 1 0 33.313333u 20n 0 33.333333u)
```

- 原理图影响：本次不改任何导线、拓扑、符号位置、引脚连接或器件参数。VIN 已是原图中存在的显式网络名；Q1 漏极对应的缓存节点名为 7，因此改用显式名称作为控制模型的输入引用。
- 器件/BOM/PCB 影响：本次不要求更换器件、额定值、封装或 PCB。保留原上传工程的硬件选择，并未据此完成硬件设计复核。
- 仿真模型影响：实际载波从 100 kHz 改为 30 kHz，并修正上述 VIN 引用。CVCC 控制器、保护逻辑、IR2184 模型、其他器件模型、测试源及求解设置均未改动。V3 仍是功能等效控制器，不能证明真实 STM32 固件的行为。
- V3 普通“值”页中的旧脉冲参数保持原样；实际输出由内嵌模板产生。以后改频率时仍须改模板，不能只看普通脉冲周期框。

## 验证证据与限制

[复现脚本](../simulation/multisim14/manual-driver-30khz/patch_driver_30khz.py) 直接替换解压后 XML 原字节，不通过 XML 解析器重新保存文件。已检查：

1. 两份模板同步变更，恰好两个 XML 属性发生变化；将改动逆替换后，XML 与原件逐字节完全一致。
2. 导线、符号、端口、节点、器件参数、器件模型及仿真配置的静态指纹不变；原始上传文件字节不变。
3. 输出文件由两个独立 DCL 解码器重新解压，均得到预期 XML。
4. 从输出文件抽取载波和 PWM 方程，在 ngspice 44.2 的 PSpice 兼容模式中单独测试；固定占空比为 20%、50%、80%。这只是 PWM 子级检查，没有运行完整的手工工程。

| 固定占空比 | 测得周期 | 测得频率 | 测得占空比 |
|---|---|---|---|
| 20% | 33.335 µs | 29,998.50 Hz | 19.9869% |
| 50% | 33.335 µs | 29,998.50 Hz | 49.9675% |
| 80% | 33.335 µs | 29,998.50 Hz | 79.9480% |

测试最大步长为 5 ns。精确哈希、结构检查及节点证据在 [patch_checks.json](../simulation/multisim14/manual-driver-30khz/results/patch_checks.json)，测试网表与日志在同目录。

尚未在 Windows Multisim 14 中打开或运行修改版，不能将解压和静态检查等同于客户端验证。没有验证完整闭环稳定性、功率启动、驱动死区、保护全工况、固件、整机效率或硬件安全性。

## 下一步客户端检查

先保持 V1=0 V、V_EN=0 V，保留当前其他设置，在 Multisim 打开修改版，运行短瞬态，观察 U1 的 IN（原截图网络 16）。2 ms 后放大相邻脉冲，周期应约 33.33 µs。此步只确认实际 PWM 已改频；功率启动检查另行进行。当前故障测试源在 7 ms 动作，长时间功率测试前需另行安排该测试源。
